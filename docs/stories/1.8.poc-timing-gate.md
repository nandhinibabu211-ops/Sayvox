# Story 1.8: PoC timing gate

## Status
Draft

## Story
**As the** team,
**we want** to measure release → inserted on 20 phrases,
**so that** we know the PoC meets the < 1 s bar before Phase 2 starts.

## Acceptance Criteria
1. `eval/timing` harness records release → inserted for 20 scripted phrases.
2. Report shows p50 and p95; the gate passes when all 20 are < 1 s.
3. Results are committed under `eval/results/phase1-<date>.json`.

## Tasks / Subtasks
- [ ] Client instrumentation with a monotonic clock: `t_release`, `t_commit_sent`, `t_committed`, `t_paste_done` (AC 1)
- [ ] Debug-only harness mode: inject WAV PCM into the audio pipeline and simulate press/release (AC 1)
- [ ] `eval/timing/phrases-phase1/`: 20 consented WAV recordings incl. Indian English, with expected text (AC 1)
- [ ] `eval/timing/run.ts`: run all phrases, compute p50/p95, print pass/fail (AC 2)
- [ ] JSON output with per-phrase timings and environment (OS, network, region) (AC 3)

## Dev Notes
- Gate: `docs/epics/epic-1-foundation-dictation-poc.md`; Constitution III.
- Results hold timings and a match/no-match flag only — no transcribed text.

### Testing
- Run on Windows on a home connection and an office network; record both.
