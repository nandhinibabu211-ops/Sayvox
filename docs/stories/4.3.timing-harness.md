# Story 4.3: Timing harness

## Status
Draft

## Story
**As the** team,
**we want** end-to-end latency measured per mode and model,
**so that** we know whether we meet the 1 s / 3 s budgets.

## Acceptance Criteria
1. Replays audio through the real pipeline (staging) and records release→inserted, STT commit, TTFT and total.
2. Reports p50/p95 per mode and model.

## Tasks / Subtasks
- [ ] Extend Story 1.8 harness to run against staging API with real Scribe + OpenRouter (AC 1)
- [ ] Option `--preset` and `--model` overrides (staging-only header `x-eval-model`) (AC 2)
- [ ] Repeat each case N=5 to stabilise percentiles (AC 2)
- [ ] Report `eval/results/timing-<date>.md` table: mode × model → p50/p95 for each stage (AC 2)
- [ ] Fail exit code if prompt p95 > 3 s or dictation p95 > 1 s (AC 2)

## Dev Notes
- The eval model override header must be rejected in prod (config flag).

### Testing
- Dry-run mode against mocks for CI; real run nightly/staging.
