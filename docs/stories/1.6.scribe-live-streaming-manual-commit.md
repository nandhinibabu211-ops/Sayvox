# Story 1.6: Scribe v3 Live streaming with manual commit

## Status
Draft

## Story
**As a** user,
**I want** to see words appear while I speak and get the final text on release,
**so that** I trust the app is hearing me and the result arrives instantly.

## Acceptance Criteria
1. Client opens the Scribe WS with token, `audio_format=pcm_16000`, `commit_strategy=manual`.
2. Streams audio chunks as `input_audio_chunk` while the hotkey is held.
3. `partial_transcript` updates overlay text live.
4. On release, sends commit; `committed_transcript` resolves the final text; socket closes.
5. Commit → committed transcript time is measured and logged locally (no text logged).

## Tasks / Subtasks
- [ ] `apps/desktop/src/services/scribeClient.ts`: `start(token, opts)`, `sendChunk(pcm)`, `commit(): Promise<string>`, `abort()` (AC 1, 2, 4)
- [ ] Open the WS on press in parallel with audio start; queue chunks until `open`, then flush in order (AC 2)
- [ ] Efficient base64 encoding of PCM chunks (reuse buffers) (AC 2)
- [ ] `partial_transcript` → overlay store; `committed_transcript` → resolve and close (AC 3, 4)
- [ ] Commit timeout 2 s → reject with `STT_TIMEOUT` (retry policy is Story 3.7)
- [ ] Measure `sttCommitMs`; local debug log records the number only (AC 5)
- [ ] Pipeline wiring: press → dev token (Story 1.5) → scribeClient + audio; release → commit (AC 1–4)
- [ ] Contract tests against mock Scribe server `apps/desktop/test/mocks/scribeServer.ts` (AC 1–4)

## Dev Notes
