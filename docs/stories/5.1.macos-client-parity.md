# Story 5.1: macOS client parity

## Status
Draft

## Story
**As a** macOS user,
**I want** the same hold-to-talk experience as on Windows,
**so that** Sayvox works on my Mac.

## Acceptance Criteria
1. `CGEventTap` hotkey for Ctrl+Shift hold; non-activating `NSPanel` overlay; app runs as a menu-bar (Accessory) app.
2. Audio capture, active-app detection (bundle id), Cmd+V paste with clipboard restore; Microphone, Accessibility and Input Monitoring permission onboarding.
3. All Epic 1/3 behaviours pass on macOS 13+ (Apple Silicon and Intel), tested on real hardware.

## Tasks / Subtasks
- [ ] `src-tauri/src/hotkey/macos.rs`: `CGEventTap` on `flagsChanged` for Control+Shift; reuse the shared state machine (AC 1)
- [ ] Activation policy Accessory; overlay as `NSPanel` with non-activating style mask (AC 1)
- [ ] `active_app/macos.rs`: `NSWorkspace.frontmostApplication` bundle id; window title via Accessibility API for browser mapping (AC 2)
- [ ] `insert/macos.rs`: `NSPasteboard` snapshot of all items; `CGEventPost` Cmd+V; restore (AC 2)
- [ ] `NSMicrophoneUsageDescription`; `AXIsProcessTrustedWithOptions` check; onboarding screens with "Open System Settings" (AC 2)
- [ ] Run the Epic 1 / Epic 3 manual matrix and timing harness on macOS 13–15 (AC 3)

## Dev Notes
- ADR-010: Windows was built first; macOS is added here behind the same per-OS traits.
- ADR-007: builds are self-signed, not notarized; Gatekeeper "Open Anyway" applies (Story 5.2).
- Needs a real Mac; CI macOS runners can build but can't test permissions or paste.

### Testing
- `cargo test` on macos-latest runner; manual matrix: TextEdit, Notes, Safari, Chrome, Slack, VS Code, Cursor, Terminal.
