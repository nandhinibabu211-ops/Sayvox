# Story 6.5: Provider capacity and spend controls

## Status
Draft

## Story
**As the** operator,
**I want** provider capacity sized for peak and spend capped,
**so that** launch traffic neither fails nor surprises us on the bill.

## Acceptance Criteria
1. ElevenLabs plan sized to expected peak concurrency; the concurrency limit is documented.
2. Spend caps are set in the ElevenLabs and OpenRouter dashboards, plus a Google Cloud budget alert; daily spend alert at 2× the 7-day average.
3. A weekly reconciliation job compares client-reported audio seconds with ElevenLabs usage.

## Tasks / Subtasks
- [ ] Estimate peak simultaneous dictations from beta data; confirm per-plan STT concurrency with ElevenLabs; choose tier; apply to Startup Grants Program (AC 1)
- [ ] Document in `docs/runbooks/capacity.md` (AC 1)
- [ ] Set dashboard spend caps; `usage_daily` cost aggregation job + alert rule (AC 2)
- [ ] `apps/api/src/jobs/reconcile.ts`: pull ElevenLabs usage API, compare to `sum(audio_seconds)`, alert if drift > 5 % (AC 3)
- [ ] Track `active_scribe_sessions` gauge (started − ended) to see concurrency headroom (AC 1)
