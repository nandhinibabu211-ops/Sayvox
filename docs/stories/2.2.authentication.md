# Story 2.2: Authentication

## Status
Draft

## Story
**As a** user,
**I want** to sign in once and stay signed in,
**so that** the app just works whenever I press the hotkey.

## Acceptance Criteria
1. Client signs in via Google Identity Platform (email or Google account) in the system browser and returns via the `sayvox://auth` deep link.
2. Tokens are stored in the OS keychain (macOS Keychain / Windows Credential Manager).
3. API verifies the JWT via JWKS on every `/v1/*` route except `/healthz`, `/v1/client-config`, `/v1/billing/webhook`.
4. First authenticated request lazily creates `users` + default `settings` rows.
5. Expired/invalid tokens → `401 UNAUTHENTICATED`; the client refreshes silently.

## Tasks / Subtasks
- [ ] Register `sayvox://` scheme via `tauri-plugin-deep-link` (macOS + Windows) (AC 1)
- [ ] Sign-in page on Firebase Hosting (Firebase JS SDK, email + Google providers); the desktop app opens it with a one-time `state` and a loopback port; the page POSTs the ID + refresh tokens to `http://127.0.0.1:<port>/callback` (never in the URL); then the `sayvox://auth` deep link brings the app to front (AC 1)
- [ ] Token refresh via the Identity Platform secure-token endpoint using the stored refresh token (AC 5)
- [ ] `src-tauri/src/keychain/`: `keyring` crate wrapper; tokens never in localStorage or files (AC 2)
- [ ] `apps/api/src/modules/auth/plugin.ts`: verify Identity Platform ID tokens (`firebase-admin` `verifyIdToken`, or `jose` with Google's JWKS cached); check `iss = https://securetoken.google.com/<project>`, `aud = <project>`, `exp` (AC 3)
- [ ] Route-level `config: { public: true }` opt-out for the three public routes (AC 3)
- [ ] `ensureUser()` upsert on `auth_provider_id` inside one transaction with default settings (AC 4)
- [ ] Client `apiClient` refresh-on-401 with single-flight lock, then retry once (AC 5)
- [ ] Onboarding Sign-in screen per `docs/front-end-spec.md` §3.1 (AC 1)
- [ ] Tests: valid/expired/wrong-issuer JWT; lazy-create idempotent under concurrent requests (AC 3, 4)

## Dev Notes
- Provider: Google Identity Platform (ADR-006, research R9). Local dev uses the Firebase Auth emulator.
- Hot path: JWKS must be cached in memory so `/session/start` stays < 150 ms.

### Testing
- Unit + integration (`fastify.inject` with locally signed JWTs and a stub JWKS server).
- Manual: sign in, quit, relaunch → still signed in; revoke session → silent refresh fails → sign-in screen.
