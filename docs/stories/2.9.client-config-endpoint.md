# Story 2.9: Client config endpoint

## Status
Draft

## Story
**As the** operator,
**I want** a config endpoint for minimum client version, kill switch and rollout flags,
**so that** I can force updates or pause the service without shipping a release.

## Acceptance Criteria
1. `GET /v1/client-config` returns `minClientVersion`, `killSwitch`, `rolloutFlags` (rollout percent / inRollout).
2. Client checks on start and every 30 min; enforces forced-update and kill-switch states.

## Tasks / Subtasks
- [ ] `apps/api/src/modules/config/clientConfig.ts`: read `cfg:client` from Redis with env defaults; public route (AC 1)
- [ ] `inRollout` = `hash(installId) % 100 < rolloutPercent` (AC 1)
- [ ] Admin script `pnpm --filter api cfg:set killSwitch=true` (writes Redis; audited in logs) (AC 1)
- [ ] Client poller on start, every 30 min, and on wake from sleep (AC 2)
- [ ] Forced-update blocking window and kill-switch paused state per `docs/front-end-spec.md` §3.5 (AC 2)
- [ ] `/session/start` also enforces both states server-side (Story 2.4) (AC 2)
- [ ] Unit tests for semver comparison and rollout bucketing (AC 1, 2)

## Dev Notes
- Install id: random UUID generated at first launch, stored locally; not linked to analytics identity.
- Used by Story 5.3 (staged rollout) and Story 6.6 (kill-switch drill).

### Testing
- Contract test; manual toggle in staging.
