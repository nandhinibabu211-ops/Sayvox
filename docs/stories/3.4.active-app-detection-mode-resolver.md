# Story 3.4: Active-app detection and mode resolver

## Status
Draft

## Story
**As a** user,
**I want** Sayvox to pick Prompt mode in Cursor and Email mode in Gmail automatically,
**so that** I get the right output without switching modes.

## Acceptance Criteria
1. Rust `active_app` returns the foreground exe name + window title (title used only locally to identify browser-hosted apps like Gmail; only the app id is sent).
2. Mode resolver: per-app override → built-in default map (Cursor/VS Code → Prompt; Gmail/Outlook → Email; Slack/Teams → Email/Slack) → user default.
3. Overlay shows the mode badge; clicking it cycles the mode for the current press.

## Tasks / Subtasks
- [ ] `src-tauri/src/active_app/windows.rs`: `GetForegroundWindow` → `GetWindowThreadProcessId` → `QueryFullProcessImageNameW` for exe name; `GetWindowTextW` for title (AC 1)
- [ ] Capture the active app at hotkey **press** (before the overlay could affect focus) (AC 1)
- [ ] `src-tauri/src/active_app/browser_map.rs`: title patterns → virtual app ids (`web:gmail`, `web:outlook`, `web:slack`, `web:chatgpt`, `web:claude`) (AC 1)
- [ ] `apps/desktop/src/services/modeResolver.ts` with built-in map in `packages/shared/src/appModes.ts` (AC 2)
- [ ] Overlay badge component; click/shortcut cycles mode for this press only (AC 3)
- [ ] Unit tests `modeResolver.test.ts`: override precedence, browser ids, unknown app (AC 2)

## Dev Notes
- Window titles never leave the device (Constitution I); `targetApp` ≤ 200 chars, app id only.
- Windows only (ADR-010).

### Testing
- Unit tests; manual check with Cursor, VS Code, Chrome (Gmail tab vs other tab), Slack.
