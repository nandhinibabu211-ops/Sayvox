# Story 5.3: Auto-update with staged rollout

## Status
Draft

## Story
**As the** operator,
**I want** updates delivered gradually with signed manifests,
**so that** a bad release reaches few users and can't be tampered with.

## Acceptance Criteria
1. Tauri updater with signed manifests.
2. Rollout percentage from `/v1/client-config` (10 → 50 → 100 %), bucketed by stable install id.
3. Minimum supported version forces update.

## Tasks / Subtasks
- [ ] Generate updater key pair; public key in `tauri.conf.json`; private key in CI secrets (AC 1)
- [ ] Release workflow publishes `latest.json` manifest per platform to Cloud Storage behind Cloud CDN (AC 1)
- [ ] Client checks for updates only when `inRollout` is true (Story 2.9) (AC 2)
- [ ] Download in background; install on next idle (not during a dictation) or app restart (AC 2)
- [ ] Forced update path when below `minClientVersion` (AC 3)
- [ ] Runbook `docs/runbooks/release.md`: bump rollout 10 → 50 → 100 with metric checks between steps (AC 2)

## Dev Notes
- Rollback = publish previous version as new manifest + raise `minClientVersion` only if needed.

### Testing
- Staging channel with two test versions; verify bucketing and forced update.
