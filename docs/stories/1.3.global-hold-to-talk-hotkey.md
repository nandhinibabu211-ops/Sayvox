# Story 1.3: Global hold-to-talk hotkey

## Status
Draft

## Story
**As a** user,
**I want** to hold Ctrl+Shift to talk and release to stop,
**so that** dictation is one gesture from any app.

## Acceptance Criteria
1. Rust `hotkey` module emits `press` and `release` events for Ctrl+Shift held together, from any app.
2. Holds shorter than 300 ms are treated as accidental and emit `cancel`.
3. Overlay appears within 50 ms of press.
4. Key-repeat does not emit multiple presses.
5. Unit tests cover the press/release/cancel state machine.

## Tasks / Subtasks
- [ ] `src-tauri/src/hotkey/state.rs`: pure state machine (Idle → Pressed → Held → Released/Cancelled) with injected clock (AC 2, 4, 5)
- [ ] Windows backend: `SetWindowsHookExW(WH_KEYBOARD_LL)` on a dedicated thread with message loop; track `VK_LCONTROL/RCONTROL` + `VK_LSHIFT/RSHIFT` (AC 1)
- [ ] Keep the OS hook behind a small trait so the state machine is testable without Windows (ADR-010: Windows only)
- [ ] Ignore chord if any other non-modifier key is pressed while held (avoid conflict with Ctrl+Shift+X shortcuts)
- [ ] Emit Tauri events `hotkey://press|release|cancel`; overlay listens and shows (AC 3)
- [ ] Measure press → overlay visible; log locally (AC 3)
- [ ] Unit tests for state machine incl. repeat, short hold, interleaved key (AC 5)

## Dev Notes
- Hotkey must be configurable later (Settings → General, Story 2.6); keep binding as data.
- Releasing the key is the end-of-speech signal; do not add silence detection.
- A press triggers `session/start` usage of the pre-fetched token (Story 2.4); for PoC, the dev token endpoint (Story 1.5).

### Testing
- `cargo test -p sayvox-desktop hotkey::`
- Manual: hold in Notepad, Chrome, Slack; confirm no stray characters typed and Ctrl+Shift+T / Ctrl+Shift+Esc still work.
