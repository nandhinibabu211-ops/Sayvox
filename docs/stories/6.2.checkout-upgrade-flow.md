# Story 6.2: Checkout and upgrade flow

## Status
Draft

## Story
**As a** user,
**I want** to upgrade in a couple of clicks when I hit a limit,
**so that** I can keep dictating.

## Acceptance Criteria
1. `POST /v1/billing/checkout` returns a hosted checkout URL, opened in the system browser.
2. Upgrade buttons appear in the overlay (quota hit) and the Usage screen.

## Tasks / Subtasks
- [ ] `apps/api/src/modules/billing/checkout.ts`: validate plan, select provider, create session with success URL `sayvox://billing/success` (AC 1)
- [ ] Client opens URL via `tauri-plugin-opener`; handles deep-link return by refreshing usage/settings (AC 1)
- [ ] Overlay quota-hit state with Upgrade CTA; Usage screen Upgrade button (AC 2)
- [ ] Pricing comes from `plans` (no hard-coded prices in client) (AC 2)
- [ ] Contract test for checkout route (AC 1)
