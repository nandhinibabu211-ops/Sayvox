# Story 5.4: Observability

## Status
Draft

## Story
**As the** operator,
**I want** dashboards and alerts for latency, errors, fallbacks and crashes,
**so that** I find problems before users report them.

## Acceptance Criteria
1. Backend errors go to Google Cloud Error Reporting; client crashes go via `POST /v1/telemetry`; request bodies and text are never included.
2. OTel metrics → Cloud Monitoring dashboards for every signal in architecture §16.
3. Alerts configured in Cloud Monitoring with the thresholds listed there.
4. Text-free product events via `POST /v1/telemetry` → Cloud Logging → BigQuery: `dictation_started`, `dictation_inserted`, `mode_changed`, `fallback_used`, `quota_hit`.

## Tasks / Subtasks
- [ ] `apps/api/src/modules/telemetry/`: Zod schema per `contracts/openapi.yaml` (`additionalProperties: false`, enum/number fields only); crash → Error Reporting, event → structured log (AC 1, 4)
- [ ] Client crash capture (Rust panic hook + JS `onerror`) → batch to `/v1/telemetry`; strip string literals from stacks (AC 1)
- [ ] Backend `@google-cloud/error-reporting` with body scrubbing (AC 1)
- [ ] OTel SDK with Google Cloud Monitoring + Cloud Trace exporters (AC 2)
- [ ] Metrics: `release_to_insert_ms{mode,model,region}`, `stt_commit_ms`, `scribe_disconnects_total`, `llm_ttft_ms`, `llm_fallback_total`, `http_errors_total`, `session_start_ms` (AC 2)
- [ ] Client timings arrive via `/session/end` and are emitted as backend metrics (AC 2)
- [ ] Cloud Monitoring dashboards and alert policies as Terraform in `infra/observability/` (AC 2, 3)
- [ ] Alerts: p95 prompt > 3 s, dictation > 1.2 s; disconnects > 1 %; fallback > 5 % for 10 min; errors > 1 %; `/session/start` p95 > 250 ms; new crash type (AC 3)
- [ ] Log sink: telemetry events → BigQuery dataset `sayvox_events` (partitioned by day); opt-out toggle in Privacy screen (AC 4)
- [ ] Privacy test: dictate a known phrase, assert it is absent from Cloud Logging, Error Reporting and BigQuery (AC 1, 4)
