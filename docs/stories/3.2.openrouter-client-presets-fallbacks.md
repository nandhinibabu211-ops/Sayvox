# Story 3.2: OpenRouter client with presets and fallbacks

## Status
Draft

## Story
**As a** user,
**I want** rewrites to arrive fast even when a model is slow or down,
**so that** prompt and email modes stay within 3 s.

## Acceptance Criteria
1. Single keep-alive undici pool to OpenRouter.
2. Presets from config: Fastest, Balanced, Cheapest → ordered model slug lists; slugs validated at startup against OpenRouter `/models` (warn on mismatch).
3. Request: `stream: true`, `max_tokens: 600`, `temperature: 0.2`, lowest reasoning, provider routing restricted to no-train/no-retain providers.
4. Per-attempt 1.5 s first-token deadline; on miss or error, abort and try the next model.
5. Records `model_used`, `fallback_used`, token counts, `ttft_ms`, `total_ms`.

## Tasks / Subtasks
- [ ] Verify slugs, reasoning param and provider routing fields (research R2, task T019) (AC 2, 3)
- [ ] `apps/api/src/lib/openrouter/pool.ts`: `undici.Pool` with keep-alive, warmed at startup (AC 1)
- [ ] `apps/api/src/modules/config/presets.ts`: env/Redis-driven `{fastest, balanced, cheapest}` → slugs (AC 2)
- [ ] `validateSlugs.ts`: fetch `/models` on boot; log warning + metric on mismatch (AC 2)

- [ ] Overall budget 8 s → terminal error (AC 4)
- [ ] Return a result object with metrics for the rewrite module (AC 5)
- [ ] Unit tests with mock OpenRouter (normal, 5xx, slow TTFT, cut stream) (AC 4)
