# Story 1.2: Tauri shell with tray and overlay window

## Status
Draft

## Story
**As a** user,
**I want** the app to live in the menu bar/tray with an overlay that appears on demand,
**so that** it never gets in my way.

## Acceptance Criteria
1. Tauri v2 app launches into tray/menu bar with Settings and Quit items.
2. A transparent, always-on-top, non-focusable overlay window exists, hidden by default.
3. Showing the overlay does not steal focus from the frontmost app (verified in Notepad, Word and a browser).
4. Overlay follows OS light/dark.

## Tasks / Subtasks
- [ ] Configure `tauri.conf.json`: no main window on launch; `overlay` window (`transparent`, `decorations: false`, `alwaysOnTop`, `focus: false`, `skipTaskbar`) (AC 2)
- [ ] Windows: `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST` on overlay; show with `SW_SHOWNOACTIVATE` (AC 3)
- [ ] Keep window setup behind a per-OS trait; macOS `NSPanel` comes in Story 5.1 (ADR-010)
- [ ] Tray icon + menu (Settings opens settings window; Quit) (AC 1)
- [ ] Overlay UI shell with states from `docs/front-end-spec.md` §3.2 (Hidden, Listening placeholder) (AC 2)
- [ ] `prefers-color-scheme` tokens for light/dark (AC 4)
- [ ] Manual test checklist for focus retention (AC 3)

## Dev Notes
- Overlay size/position: `docs/front-end-spec.md` §4.
- Overlay must show within 50 ms of hotkey (Story 1.3) — keep window pre-created and hidden; never create on demand.

### Testing
- Manual focus test matrix: Notepad, Word, Chrome, Edge, Slack, VS Code.
- Snapshot test of overlay component states.
