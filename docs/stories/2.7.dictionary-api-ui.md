# Story 2.7: Dictionary API and UI

## Status
Draft

## Story
**As a** user,
**I want** to add names and jargon to a custom dictionary,
**so that** words like "Zoho" and "Zia" are transcribed correctly.

## Acceptance Criteria
1. `GET/POST/DELETE /v1/dictionary`; case-insensitive uniqueness; term ≤ 64 chars.
2. Plan `dictionary_limit` enforced.
3. Terms are returned as keyterms by `/session/start`.
4. Dictionary UI shows count/limit.

## Tasks / Subtasks
- [ ] `apps/api/src/modules/dictionary/`: list, add (trim, collapse spaces, reject control chars), delete by id (AC 1)
- [ ] Duplicate → `409 CONFLICT`; at limit → `403 FORBIDDEN` with limit in message (AC 1, 2)
- [ ] Invalidate `settings:{userId}` cache on change so keyterms refresh (AC 3)
- [ ] Cap keyterms sent to Scribe at the provider maximum (R1); prefer most recent if over (AC 3)
- [ ] `apps/desktop/src/settings/Dictionary.tsx`: add input, list with delete, `n / limit` counter, limit message (AC 4)
- [ ] Client invalidates its prefetched session after a dictionary change so the next press uses new keyterms (AC 3)
- [ ] Contract test `apps/api/test/contract/dictionary.test.ts` (AC 1–3)

## Dev Notes
- Keyterms add ~$0.08/audio hour; only send them when the user has terms.
- Dictionary terms are user data: removed on account deletion (Story 5.7).

### Testing
- Contract tests; manual check that a new term changes transcription on the next press.
