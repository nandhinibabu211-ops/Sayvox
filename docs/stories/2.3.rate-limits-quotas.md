# Story 2.3: Rate limits and quotas

## Status
Draft

## Story
**As the** operator,
**I want** per-user rate limits and audio quotas,
**so that** cost is bounded and abuse is contained.

## Acceptance Criteria
1. Redis token-bucket rate limit per user (default 30 session starts/min).
2. Daily and monthly audio-minute quotas checked from Redis counters (reconciled from `usage_daily`).
3. Exceeded → `429 RATE_LIMITED` or `402 QUOTA_EXCEEDED` with reset time.
4. Each session receives `maxSessionSeconds` (default 300 s).

## Tasks / Subtasks
- [ ] `apps/api/src/modules/limits/rateLimit.ts`: atomic Lua token bucket on `rl:{userId}` (AC 1)
- [ ] `apps/api/src/modules/limits/quota.ts`: read `quota:day:*` and `quota:month:*`; compare to plan limits (AC 2)
- [ ] Rebuild counters from `usage_daily` on cache miss (AC 2)
- [ ] Error responses with `resetAt` per `contracts/openapi.yaml` `Error` schema (AC 3)
- [ ] `maxSessionSeconds` from plan/config, returned by `/session/start` (AC 4)
- [ ] Config overrides via env for staging (low caps) (AC 1, 2)
- [ ] Unit tests: bucket refill, boundary at exactly the cap, UTC day rollover, month rollover (AC 1–3)
