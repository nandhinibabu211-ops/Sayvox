# Story 4.2: Quality scorer

## Status
Draft

## Story
**As the** team,
**we want** an automated scorer comparing our output to the Lemon baseline,
**so that** every prompt or model change is judged consistently.

## Acceptance Criteria
1. Rule checks: no preamble, no invented facts (entity overlap), fillers removed, self-corrections applied.
2. LLM-judge pairwise comparison vs Lemon baseline with a fixed rubric and seed.
3. Output: per-mode win/tie/loss and WER for raw STT.

## Tasks / Subtasks
- [ ] `eval/scorer/rules.ts`: preamble regex, filler list, required-facts presence, forbidden-content absence, entity overlap (AC 1)
- [ ] `eval/scorer/judge.ts`: pairwise judge with randomized A/B order, temperature 0, fixed rubric in `eval/scorer/rubric.md`; judge model differs from the generating model (AC 2)
- [ ] `eval/scorer/wer.ts`: WER of Scribe transcript vs reference, normalized (AC 3)
- [ ] `eval/run.ts`: runs pipeline over dataset (audio → Scribe → rewrite), writes `eval/results/quality-<date>.json` + markdown summary (AC 3)
- [ ] Pass criterion: wins + ties ≥ losses per mode (quality ≥ Lemon) and zero injection failures (AC 3)
