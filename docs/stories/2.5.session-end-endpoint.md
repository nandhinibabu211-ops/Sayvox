# Story 2.5: `POST /v1/session/{id}/end`

## Status
Draft

## Story
**As the** operator,
**I want** each dictation closed with its timings and audio seconds,
**so that** usage, cost and latency are measured accurately.

## Acceptance Criteria
1. Accepts `SessionEndRequest`; validates session ownership.
2. Updates the session row with audio seconds, timings and status; upserts `usage_daily`; increments Redis quota counters.
3. Clamps reported `audioSeconds` to `maxSessionSeconds` and to the session's wall-clock duration.
4. Idempotent on repeated calls.

## Tasks / Subtasks
- [ ] `apps/api/src/modules/session/end.ts` with ownership check (`404` if not the user's) (AC 1)
- [ ] Map `insertResult` → session status (`inserted→completed`, `raw_fallback`, `discarded|failed→failed`) (AC 2)
- [ ] Single transaction: update session (only if `status='started'`), upsert `usage_daily` with `audio_seconds`, `requests`, `stt_cost_usd` (= seconds × $0.22/3600, + keyterm rate if used) (AC 2, 4)
- [ ] Increment `quota:day` and `quota:month` only when the row actually transitioned (AC 2, 4)
- [ ] Clamp: `min(audioSeconds, maxSessionSeconds, now - started_at)` (AC 3)
- [ ] Client sends end via a fire-and-forget queue with retry (persist pending ends locally — metadata only) (AC 4)
- [ ] Contract test `apps/api/test/contract/session-end.test.ts`: double call, clamp, foreign session (AC 1–4)
