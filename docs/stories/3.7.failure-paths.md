# Story 3.7: Failure paths

## Status
Draft

## Story
**As a** user,
**I want** my words to survive network and provider failures,
**so that** I never have to repeat myself.

## Acceptance Criteria
1. Scribe drop mid-utterance: fetch a new token, reconnect once, replay the ring buffer, commit.
2. All models fail or total > 8 s: paste the raw transcript; session `raw_fallback`; overlay shows a subtle notice.
3. Contract tests simulate WS drop, OpenRouter 5xx, TTFT timeout and partial stream cut.

## Tasks / Subtasks
- [ ] `scribeClient`: on unexpected close/error before commit → `tokenCache.take()` (or fresh `/session/start`) → reconnect → replay ring buffer in chunks → continue live or commit if released (AC 1)
- [ ] Second failure → overlay Error, session end `failed` (AC 1)
- [ ] `pipeline.ts`: on rewrite `error` event, network error, or 8 s budget → insert raw transcript (post local cleanup) (AC 2)
- [ ] Partial stream cut after tokens: insert raw transcript rather than a truncated rewrite (AC 2)
- [ ] Overlay notice "Inserted original text — AI rewrite unavailable" (AC 2)
- [ ] Mock Scribe/OpenRouter scenarios in contract tests (AC 3)
- [ ] Session end includes `scribeRetried` flag (AC 1)
