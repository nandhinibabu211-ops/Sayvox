# Story 6.3: Billing webhooks

## Status
Draft

## Story
**As the** operator,
**I want** subscription events applied reliably,
**so that** users get the plan they paid for — exactly once.

## Acceptance Criteria
1. `POST /v1/billing/webhook` verifies signatures, is idempotent (event id store), updates `subscriptions` and `users.plan_id`.
2. Handles created, renewed, past_due, cancelled.

## Tasks / Subtasks
- [ ] Raw-body capture for signature verification (Fastify `addContentTypeParser` for this route) (AC 1)
- [ ] Insert into `billing_events (provider, event_id)`; on conflict return 200 without reprocessing (AC 1)
- [ ] Event mapping per provider → `subscriptions` upsert + `users.plan_id` (cancelled/past_due grace → `free`) (AC 2)
- [ ] Invalidate `settings:{userId}` and quota caches on plan change (AC 1)
- [ ] Do not persist webhook payloads (AC 1)
- [ ] Tests with signed fixture events for each type, plus replay (AC 1, 2)

## Dev Notes
