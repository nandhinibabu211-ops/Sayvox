# Story 2.1: Database schema and migrations

## Status
Draft

## Story
**As a** developer,
**I want** the Postgres schema defined in code with migrations,
**so that** every environment is reproducible and privacy rules are enforced structurally.

## Acceptance Criteria
1. Drizzle schema + migrations for `users`, `plans`, `subscriptions`, `settings`, `dictionary_terms`, `sessions`, `usage_daily` (and `billing_events`) per `specs/001-voice-to-prompt-mvp/data-model.md`.
2. No column stores transcript or rewrite text.
3. Seed creates `free` and `pro` plans.
4. Least-privilege DB role for the API (no DDL rights in prod).

## Tasks / Subtasks
- [ ] `apps/api/src/lib/db/schema.ts`: tables, enums (`user_status`, `preset`, `mode`, `insert_mode`, `session_status`, `billing_provider`) (AC 1)
- [ ] Constraints: `dictionary_terms` unique `(user_id, lower(term))`; `ON DELETE CASCADE` from every user-owned table (AC 1)
- [ ] Indexes: `sessions(user_id, started_at desc)`, partial `sessions(status) where status='started'`, `usage_daily` PK (AC 1)
- [ ] `drizzle-kit generate` → `apps/api/drizzle/0001_init.sql`; `pnpm --filter api db:migrate` script (AC 1)
- [ ] Schema lint test: fail if any column name matches `/transcript|rewrite|text|content|body/` (AC 2)
- [ ] `apps/api/drizzle/seed.ts`: `free` plan per ADR-004 (10 min/day, 120 min/month, Balanced + Cheapest, 25 terms) and `pro` plan (values set by owner, T5) (AC 3)
- [ ] SQL for roles: `sayvox_migrator` (DDL) and `sayvox_app` (DML on app tables only) (AC 4)
- [ ] Integration test with testcontainers Postgres: migrate up, seed, cascade delete (AC 1, 3)

## Dev Notes
- Canonical model: `specs/001-voice-to-prompt-mvp/data-model.md`; architecture §4 and §9.
- Use `gen_random_uuid()` (pgcrypto) and `timestamptz` everywhere.
- Database: Cloud SQL for PostgreSQL 16 (ADR-006), reached from Cloud Run via the Cloud SQL connector; app-side pool (`pg` pool, size tuned per instance) — keep total connections under the Cloud SQL tier limit.
